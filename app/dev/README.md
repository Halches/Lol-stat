# Проверка окон без игры

## Новый драфт в разработке

`sim_native_draft.py` запускает настоящий `ui.App` с изолированными временными
настройками и демонстрационными данными. Скрипт отключает опрос клиента, загрузку
статистики и проверку обновлений; ничего не экспортирует в клиент.

```bash
SIM_OUT=/tmp/native-draft SIM_ASSETS_JSON=/path/to/assets.json xvfb-run -a -s "-screen 0 1920x1080x24" python3 app/dev/sim_native_draft.py
```

Запускать из корня репозитория. `SIM_ASSETS_JSON` — необязательный файл того же
формата, что `app/assets.json`. Дополнительные параметры: `SIM_GEOMETRY` (например,
`1366x768+0+0`), `SIM_SCALE` (100 или 150), `SIM_THEME` (ключ существующей темы).
`SIM_BUILD_CONTEXT=matchup SIM_BUILD_VARIANT=win` показывает выбранную сборку
против оппонента по винрейту. Для полного снимка использовать виртуальный экран
и окно 1920×1440; в обычном окне 1920×1080 доступна прокрутка. Центральная часть
сохраняется дополнительно в `native-draft-builds-detail.png`. Матчап подставляется
из сохранённого публичного ответа; сеть и клиент в симуляции не используются.
Результат: снимки выбора и подтверждения чемпиона, `native-checks.json` с ошибками
Tk и размерами колонок. Статистику на этих снимках нельзя выдавать за живую.

Изменения драфта пока не выпускать в обновление: сначала завершить весь
согласованный перенос интерфейса и проверить Windows с настоящим клиентом.

Скрипты запускают настоящий `ui.App` с подставными данными клиента и делают скриншоты (Linux, Xvfb, ImageMagick `import`).

```bash
mkdir -p /tmp/simhome/.fonts && cp app/fonts/*.ttf /tmp/simhome/.fonts/ && HOME=/tmp/simhome fc-cache -f
cd app/dev
HOME=/tmp/simhome APPDATA=/tmp/simhome SIM_OUT=/tmp xvfb-run -a -s "-screen 0 1920x1080x24" python3.12 sim_dash.py draft   # драфт: n_draft_dash.png, n_hints.png, n_review.png, n_edit.png
HOME=/tmp/simhome APPDATA=/tmp/simhome SIM_OUT=/tmp xvfb-run -a -s "-screen 0 1920x1080x24" python3.12 sim_dash.py game    # игра: n_dash.png, n_tab*.png
HOME=/tmp/simhome APPDATA=/tmp/simhome SIM_OUT=/tmp xvfb-run -a -s "-screen 0 1920x1080x24" python3.12 sim_main.py 0       # главное окно, вкладка 0
```

Шрифты копируются в `~/.fonts`, потому что на Linux Tk не видит шрифты из папки программы (на Windows их подключает `load_fonts`).

## Рейтинг инвентаря и ручка Tab

`SIM_OUT=/tmp xvfb-run -a -s "-screen 0 1920x1080x24" python3 app/dev/sim_overlays.py`

Запускать из корня репозитория. Не требует игры, Riot API и сетевых запросов.
Проверяет перенос/размер через отдельную ручку, сохранение и её скрытие; сохраняет
скриншоты светлой и тёмной тем. На Windows дополнительно проверить: клики по самой
таблице при Tab+Alt проходят в игру, ручка не забирает фокус, работают DPI 100/125/150%.

## Автоподгонка Tab (экспериментально)

В «Виджеты и окна → Стоимость предметов по Tab» автоподгонка включена по умолчанию.
Удерживать Tab хотя бы 1–2 секунды: поиск начинается через 200 мс и повторяется
не чаще раза в 2,5 с, только пока игра в фокусе. При Alt поиск приостанавливается.
В настройках и диагностическом отчёте виден результат последнего поиска.

`tab_detect.py` сопоставляет портреты из `assets.json` с изображением игры через
OpenCV. Pillow ImageGrab захватывает клиентскую область окна через Windows GDI,
без layered-окон помощника. Изображение существует только в памяти; сеть, OCR,
чтение памяти игры и сохранение скриншотов не используются. Рабочий поток возвращает
данные в очередь; окна меняются только в потоке Tk. Результаты после отпускания Tab,
перемещения/изменения размера окна, смены состава или начала новой игры отбрасываются.

В тренировке и неполных матчах поиск запускается при любом непустом составе.
Основной способ ищет золотую рамку: две вертикальные стороны, нижний край,
разделитель шапки и центральный разделитель. Геометрию подтверждает хотя бы один
совпавший портрет в ожидаемой области строки. Это позволяет находить таблицу
с одним игроком и не принимать за неё произвольный прямоугольник.
Если рамка не подтверждена, используется прежний способ: две колонки разных команд,
общая сетка пяти строк, не менее трёх совпавших портретов с каждой стороны.
У прежнего способа горизонтальные поля вычисляются по пропорциям стандартной
таблицы LoL; новые варианты HUD могут потребовать корректировки. Отображается распознанный порядок
чемпионов; несколько неизвестных портретов не получают вымышленные подписи.
Ручная `tab_rect` не перезаписывается, последняя успешная авторамка хранится в памяти.
Составы с повторяющимися чемпионами могут не распознаваться. Таймеры смерти,
вопросительные знаки и перекрывающие таблицу окна снижают число совпадений.

Если рамка неверна или захват в эксклюзивном полноэкранном режиме даёт чёрный кадр,
проверить оконный режим без рамки или выключить автоподгонку и настроить маленькой
ручкой Tab + Alt. Большое окно всегда пропускает клики. У найденной авторамки ручка
скрыта; после выключения автоподгонки доступна снова.

Зависимости запуска из исходников: `pip install pillow opencv-python-headless==4.11.0.86 numpy==2.2.6`.
Проверки: `python app/test_core.py`, `python -m unittest discover -s app -p test_overlays.py`,
`python -m unittest discover -s app -p test_tab_detect.py`.
`sim_overlays.py` также проверяет применение результата к настоящему Tk-окну и
сохраняет `auto_overlay_night.png` / `auto_overlay_day.png`.
Тестовые изображения синтетические: они проверяют масштаб, геометрию, порядок,
отсев неверных совпадений и отмену задач, но не подтверждают точность в живой игре.
Windows CI дополнительно проверяет импорт OpenCV/NumPy внутри собранного EXE.

Регрессия тренировки: `test_one_player_practice_starts_and_applies_capture` проверяет
весь путь от удержания Tab до запуска рабочего потока и применения его результата
при одном игроке. Тесты изображений покрывают один/несколько/десять игроков,
пустую рамку, отсутствие разделителя, масштаб и сохранение прежнего способа поиска.
Статус запуска и причины паузы отображаются в основном окне настроек, а не поверх игры.

## Компактные индикаторы между игроками в Tab

В центре каждой строки показана одна разница стоимости инвентаря. Сгенерированная
стрелка над числом указывает к игроку с большей стоимостью. Синий цвет означает
преимущество нашей команды в этой паре, красный — отставание, независимо от стороны
команды на экране. При равенстве — серый `0` без стрелки; при неполных данных — `—`.
Пары берутся из фактического порядка строк. Боковые стоимости убраны. Общий
перевес, суммы и красно-синяя полоса находятся в надстройке выше шапки Tab.
Отдельный виджет «Золото по линиям» удалён.

Размер индикатора ограничен шириной центрального промежутка и высотой строки;
увеличение масштаба помощника не растягивает его на предметы и заклинания.
Проверка: `python -m unittest discover -s app -p test_tab_design.py`.
Она проверяет направление/цвет, неизвестного соперника, нулевую разницу,
прозрачность/поворот PNG и границы при нескольких игровых масштабах и масштабе
помощника 100/125/150/200%. `--selftest` проверяет наличие PNG внутри EXE.

## Hextech-оформление и закрепление

Карточки используют фактурную подложку и золотые фаски из `ui_assets/hextech-panel.png`
(9-slice), узкие щитки `hextech-badge.png` и портреты объектов из
`objective-portraits.png`. Заголовки и текст — Forum, цифры — Cinzel SemiBold
(OFL в fonts); цифры имеют светлую грань и сглаживание. Дневная тема основного окна
сохраняется, игровые подложки остаются тёмными. Без подложки текст имеет обводку.
У всех семи виджетов кроме Tab есть булавка: золотая — закреплён, перечёркнутая
приглушённая — можно двигать с модификатором. Состояние хранится в `widget_pins`.
Булавка — отдельное маленькое окно с WS_EX_NOACTIVATE; только оно принимает мышь,
когда основное окно закреплено. Alt не меняет click-through закреплённого окна.
Настройка применяется немедленно при нажатии, в том числе во время удержания Alt.

`SIM_OUT=/tmp xvfb-run -a python3 app/dev/sim_pins.py` проверяет реальные окна:
закрепление/открепление при Alt, запрет переноса, скрытие/показ значков, отсутствие
значка у Tab; сохраняет `pins_lol.png` и `pins_lol_day.png`. На Linux проверяются
состояния и компоновка; передачу клика в игру и отсутствие смены фокуса проверять
на Windows. Заголовки резервируют место под булавку.

Для предпросмотра с портретами и предметами передать `SIM_ASSETS` — папку PNG,
названных по ключам чемпионов и ID предметов. Снимки делает настоящий Tk; демонстрации
линии и покупки вызывают те же методы отрисовки, что живая игра. Не подменять такие
снимки концептом ImageGen: сравнивать все виджеты с согласованным макетом и показывать
результат, который попадёт в EXE.

Повторный поиск Tab проверяет центральный разделитель между индикаторами:
некоторые режимы захвата Windows включают layered-окна. При портретах под «?»
рамка и видимые лица задают положение и масштаб. Сравниваются края лица вокруг
знака вопроса, совместно для всей колонки, с порогом уверенности и отрывом от
альтернативы. Не использовать порядок массива игроков для угадывания строк.
Неуверенное сопоставление остаётся прочерком. При найденной рамке сначала искать
только в узких колонках портретов; полный поиск остаётся запасным вариантом.

## Экран своего пула

`sim_pool.py` запускает настоящую вкладку «Мой пул» в изолированном профиле,
без опроса клиента и обновлений. `SIM_ASSETS_JSON` задаёт существующий формат
игровых ресурсов, `SIM_POOL_PORTRAITS` — папку стандартных Data Dragon PNG
(имя файла соответствует ключу чемпиона). Доступны `SIM_THEME`, `SIM_SCALE`,
`SIM_GEOMETRY`. Симуляция проверяет реальные клики, повторное удаление,
сохранение, роль, поиск, фильтры, пустой результат и перестроение по ширине.
Сохраняет `pool-main.png`, `pool-filters.png`, `pool-filtered.png`, `pool-empty.png`,
`pool-selected.png`, `pool-compact.png` и `native-checks.json`.

## Главная с профилем и статистикой

`sim_home.py` использует тот же изолированный запуск, что и `sim_pool.py`.
Дополнительно `SIM_HOME_ITEMS` задаёт папку официальных PNG предметов по ID,
`SIM_PROFILE_ICON` — PNG иконки профиля для явно демонстрационного подключения.
Сеть, опрос клиента и обновления отключены. Профиль/уровень/подключение на
снимке демонстрационные; загруженные матчи из `data.json`. Скрипт сохраняет
`home-main.png`, `home-recent.png`, `home-other-profile.png`, `home-offline.png`,
`home-empty.png`, `home-compact.png` и отчёт `native-checks.json`. Проверяет,
что другой профиль не получает ранг активного клиента и что длинный ник и
компактное окно вызывают перестроение. Доступны темы и масштабы интерфейса;
Linux-проверка не подтверждает поведение Windows.

## История и подробности матча

`sim_history.py` использует изолированные настройки и подменённые read-only
ответы клиента. `SIM_ASSETS_JSON`, `SIM_POOL_PORTRAITS` и `SIM_HOME_ITEMS` задают
стандартные игровые ресурсы. `SIM_THEME`, `SIM_SCALE`, `SIM_GEOMETRY` управляют
основным окном, `SIM_DETAIL_GEOMETRY` — окном разбора. Сохраняет
`history-saved.png`, `history-client.png`, `history-empty.png`, `history-match.png`,
`history-refresh-error.png`, `history-saved-detail.png`, `history-compact.png` и
`native-checks.json`. Данные клиента/составы/LP на снимках демонстрационные;
сохранённый список берётся из `data.json`. Проверяется не только компоновка,
но и отбрасывание запоздалого ответа после смены аккаунта или закрытия окна.
Экспорт, обновления и настоящие сетевые запросы отключены.

## Страница чемпиона

`sim_champion.py` запускает настоящую страницу в изолированных настройках,
без клиента, сетевых запросов, экспорта и обновлений. Параметры ресурсов,
темы, масштаба и размера окна совпадают с `sim_history.py`. Все сборки,
матчапы и личные игры на снимках демонстрационные. Проверяются поиск RU/EN,
выбор роли и оппонента, одновременное переключение рун и предметов,
независимость от выбора драфта, добавление/удаление из пула, раскрытие выборок,
ошибка источника, отсутствие профиля и узкое окно. Результат:
`champion-main.png`, `champion-matchup.png`, `champion-details.png`,
`champion-search.png`, `champion-unavailable.png`, `champion-no-profile.png`,
`champion-compact.png` и `native-checks.json`.

Оффмета: `sim_champion.py` дополнительно сохраняет `champion-offmeta.png` и
`champion-offmeta-details.png`. В этом варианте используется сокращённый
фактический снимок Mobalytics Ahri / MID / EmeraldPlus / ALL / Ranked Solo
от 03.11.2026, патч 16.21; остальные показанные сборки и личные матчи — демо.
Парсер и загрузчик: `python -m unittest discover -s app -p 'test_offmeta_*.py'`.

Сборки игроков: `champion-mainer.png`, `champion-pro.png`,
`champion-players.png` показывают фактические снимки Mobalytics от 03.11.2026.
На примере Ahri источник подтвердил 3 OTP и 2 Pro. Недостающий третий Pro
обозначен текстом. Нажатие на вариант переключает его полную страницу рун,
предметы и умения, сохраняя независимость от выбора драфта. Личная статистика
предпросмотра остаётся демонстрационной. Проверки:
`python -m unittest discover -s app -p 'test_player_build*.py'`.

## Галерея «Виджеты и окна»

`sim_windows.py` запускает настоящую вкладку с изолированными настройками,
без клиента и сети. Ресурсы, тема, масштаб и размер окна задаются теми же
SIM-параметрами. Снимки: `windows-gallery.png`, `windows-enabled.png`,
`windows-preview.png`, `windows-options.png`, `windows-compact.png`.
Проверяются восемь карточек, новый default «только Tab», реальное переключение
виджета с сохранением, закрепление настоящего Overlay, исключение Tab из
булавок, увеличенный рисунок, раскрытие дополнительных настроек, одна колонка
в узком окне и сохранение ранее выбранных пользователем виджетов.
Все значения в рисунках — примеры. Семь рисунков получены существующими
методами demo/show/draw оверлеев без создания дополнительных окон. Для Tab
показаны увеличенные фрагменты, нарисованные его же render-функциями.

## Настройки подсказок и аудит условий

`sim_hints.py` открывает настоящую вкладку и редактор, используя временные
настройки, стандартные игровые ресурсы и отключённые сеть/звук. Параметры
SIM_THEME, SIM_SCALE, SIM_GEOMETRY и ресурсы совпадают с другими симуляциями.
Снимки: hints-main/support/search/empty/editor/custom/compact.png. Проверяются
фильтры роли, группы и режима, поиск, массовое изменение только показанного
набора, независимость ролей, запись своего текста, подстановка {текст},
сброс без удаления фраз и узкое окно.

`python -m unittest discover -s app -p test_hint_accuracy.py` — 30 сценариев
логики. Полный разбор источников и ограничений: HINT_AUDIT_2026-11-03.md.

Читаемость подсказок: заголовки 13 pt полужирные, короткое пояснение 11 pt;
полные условия и интервал повторов — под «Подробнее». Тест показывается
внутри карточки. Общие переключатели свёрнуты при открытии. Поиск охватывает
и короткие названия/пояснения, и полный исходный текст. Симуляция дополнительно
проверяет раскрытие условий и общих настроек; снимок hints-details.png.

Главная: проверка читаемости `sim_home.py` включает реальный Tk-экран с
крупными рангами, LP, метриками и KDA. SIM_PROFILE_ICON указывает локальный
официальный значок профиля. Шесть палитр прошли симуляции; 100/125/150%
проверены в Linux. Проверены другой профиль, отсутствие клиента и матчей,
длинный Riot ID и узкое окно. Это не проверка Windows DPI или живого клиента.

## Завершающий проход приложения

Текущий план: APP_PLAN.md; проверенные источники и ограничения:
APP_AUDIT_2026-11-03.md; запуск отдельного профиля Windows: WINDOWS_REVIEW.md.
`sim_settings.py` проверяет четыре вкладки, запись громкости и корректного
таймера, отклонение отрицательного времени и секунд вне диапазона.
`sim_native_draft.py` дополнительно выбирает оффмету и конкретного игрока,
проверяет выбранную связку, ручное закрытие/повторное открытие окна;
сохраняет native-draft-offmeta.png и native-draft-player.png. Симуляция
выполняет шаги последовательно, не закрывая окно таймером посреди проверки.

Фильтры из сохранённого модуля вики обновляются через
`tools/refresh_catalog_gameplay.py`; Lua не исполняется, при неполном покрытии
официальных ID запись отклоняется. Лорные поля и их дата не подменяются.

## Переключение виджетов и восстановление Tab

`python app/dev/sim_widget_lifecycle.py` проверяет настоящие окна Tk на Windows
или под Xvfb: переключение без пересоздания карточек, остановку расстановки,
