# Windows-бета LoL Helper

Команды запуска из каталога `beta` в PowerShell.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install PySide6-Essentials==6.12.0 pillow opencv-python-headless
.\.venv\Scripts\python desktop/qt.py
```

Откройте клиент League of Legends EUW, чтобы загрузить профиль и историю. Адрес сервиса разборов задаётся во вкладке «Настройки».

Для управления конкретной копией используйте PID её окна (GUI-процесса, а не родительского загрузчика PyInstaller):

```powershell
python desktop/automation.py --pid 12345 state
python desktop/automation.py describe --pid 12345
python desktop/automation.py --pid 12345 click menu_updates
```

Каждая копия слушает отдельный локальный адрес `<общий адрес>-pid-<PID>`, даже если общий адрес занят старой программой. `state` и `describe` возвращают `processId`, `executable`, `appVersion`, `instanceEndpoint`, `legacyEndpoint`. Явный `--pid` не переключается на общий адрес при ошибке; сервер проверяет `processId` до выполнения действия, клиент проверяет PID в успешном ответе. Без `--pid` сохранён прежний общий адрес; при нескольких копиях для точного управления обязательно укажите PID. `schema` описывает формат без подключения. Версия протокола остаётся 1.

Полное управление интерфейсом описано в `desktop/API.txt`: каталог всех кнопок и полей, `find`, чтение экранного текста и моделей, числовые параметры, варианты списков, прокрутка, окна/диалоги и позиции оверлеев. Новые обычные кнопки и поля автоматически появляются в каталоге. Для чисел CLI использует `set ... --json-value`, для полного запроса — `call --file request.json`. Проверки `enabled`, модальности, диапазонов и состояния игры сохраняются. Пароли не возвращаются в ответах. Стабильные ID строк истории содержат ID матча; удалённая строка не превращается в кнопку другого матча.

В тренировке включите «Предпросмотр в игре» в настройках или запустите приложение с флагом `--probe`. В игре удерживайте Alt, чтобы открыть шторку «Оверлеи», выбрать общую тему и масштаб 80–140% либо переместить карточку. Настройки сохраняются автоматически. При удержании Tab полоска перевеса примыкает к игровой таблице, а стрелки с разницей по золоту появляются между соперниками. Эти элементы привязаны к таблице. Шесть новых оверлеев в предпросмотре показывают демонстрационные данные.

Рабочая карточка сборки отделена от раздела «Демонстрационные оверлеи». Карточки темпа игры, золота, стоимости предметов, покупки, объектов и перевеса в Tab помечены как демо: их переключатели доступны только при включённом предпросмотре. После его завершения демонстрационные карточки скрываются; выбор примеров сохраняется для следующего предпросмотра.

Во вкладке «Обновление» показаны установленная версия и три последних стабильных выпуска GitHub. Длинные патчноуты сокращены до 650 символов или девяти строк; полное описание открывается на GitHub. Последние успешно полученные описания остаются доступны без сети. Проверка выполняется при запуске и каждые 15 минут. Новая версия появляется в уведомлении и меняет кнопку «Проверить обновления» на «Обновить». Скачивание проверяет размер и SHA-256; перезапуск запускается отдельной кнопкой после скачивания и недоступен во время драфта или матча.

Выпуск собирается workflow `.github/workflows/app.yml` из текущей Windows-беты. Перед выпуском увеличьте `VERSION` в `desktop/app_version.py` и обновите `beta/RELEASE_NOTES.txt`. Выпуск публикует `LoLHelper.exe` (совместимое имя для обновлятора старого приложения) и `SHA256SUMS.txt`. Запись становится видимой клиентам только после загрузки обоих файлов. Загрузка исходников сама по себе не заменяет публикацию GitHub Release. Служебные теги `voices`, `silero`, черновики и предварительные выпуски игнорируются. Формат API: https://docs.github.com/en/rest/releases/releases и https://docs.github.com/en/rest/releases/assets.

Установщик не использует командные скрипты: отдельная копия EXE ждёт закрытия приложения, заменяет файл в его исходном расположении и проверяет запуск новой версии. Предыдущий EXE сохраняется в `%LOCALAPPDATA%/LoLHelper/updates`; ошибка запуска восстанавливает его. При запуске из Python установка недоступна, но проверка и патчноуты работают. `--smoke` и `--probe` не запускают сетевые проверки обновлений автоматически.

Проверка логики и запуска окна.

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -p test_desktop.py
.\.venv\Scripts\python desktop/qt.py --smoke
```

Для сборки отдельного EXE используйте спецификацию Qt из этой директории.

```powershell
.\.venv\Scripts\python -m pip install pyinstaller
New-Item -ItemType Directory -Path .state -Force | Out-Null
.\.venv\Scripts\python desktop/worker.py --catalog .state/catalog.json
.\.venv\Scripts\python -m PyInstaller --noconfirm --workpath .state/qt-build --distpath out desktop/qt.spec
```
